## 0. 一句话原则

> **契约是唯一的沟通渠道。**
> 你不用读队友的代码，队友也不用读你的；大家只对着**同一份契约**写。
> 所以 —— **契约没读、对表没过，不许动手写代码。**

## 1. 一分钟上手

### 第一步：把契约喂给你的 DeepSeek

每个新对话都要做一次（DeepSeek 不记得上一个对话）：

**方法 A（推荐）**：把 `skills/pair-dev-contract/SKILL.md` 上传到对话里。

**方法 B**：新建对话，第一条消息把契约全文粘进去。

### 第二步：发「对表」指令

直接复制这段：

```
请完整阅读我上传的 SKILL.md（拾事 Shishi 软件接口契约），然后逐题回答：

1. 核心数据结构叫什么？id 的前缀是什么？
2. 快递的 expireAt 和 remindAt 分别怎么算？"剩余几天"能不能存进字段？
3. 数据源适配器 fetch() 失败时是 reject 还是 resolve？返回什么形状？
4. 为什么 history 适配器不许直接产事件？
5. 冲突判定函数叫什么？三条规则各自的 level 是什么？
6. conflicts 字段能不能写进 DbSnapshot？
7. Rust 返回的 JSON 字段名是什么大小写风格？靠什么保证？
8. 蓝牙 TX / RX 的 UUID 分别是什么？单帧 payload 上限多少字节？

每题都要引用契约里的章节号。答完先别写代码，等我确认。
```

### 第三步：拿下面这张表判分

**全对才继续。错一题就重新贴一遍契约，别将就。**

| # | 答案要点 | 出处 |
| --- | --- | --- |
| 1 | `ScheduleEvent`；前缀 `evt_`（格式 `evt_<yyyyMMdd>_<4位随机>`） | §3.1 |
| 2 | `expireAt = arriveAt + 7 天`，`remindAt = arriveAt`，`remindDaily = true`；剩余天数**永远实时算，不存字段** | §3.2 |
| 3 | **永远 resolve**，失败也返回 `AdapterResult{ ok:false, error }`，不 reject | §3.3 |
| 4 | 历史只用来**推荐**（产 `HistoryHint`）；事件必须由**用户采纳**后触发 `event_upsert` | §3.5 |
| 5 | `detectConflicts()`；`overlap` / `parcel_vs_course` / `ticket_vs_course` **全部 `warn`** | §3.6 |
| 6 | **不能**。它是只读派生字段，`db_save` 前必须剥掉 | §3.1 / §3.7 |
| 7 | **camelCase**；靠 Rust 侧 `#[serde(rename_all = "camelCase")]` | §2-8 / §7-C1 |
| 8 | TX（桌面→手机）= `...0003`，RX（手机→桌面）= `...0002`；单帧 payload **≤ 200 字节** | §3.8 |

> 🔴 如果它答得含含糊糊、开始「一般来说」「通常建议」——说明没吃进去，重贴。

## 2. 每天开工（三件事）

- [ ] **1. 拉最新**：`git pull`，先看一眼昨天谁动了什么。
- [ ] **2. 看一眼契约有没有变**：打开契约末尾的**变更日志**，比对自己上次记的版本号。变了就重新对表。
- [ ] **3. 想清楚今天碰哪块**，然后在群里发一句：

```
今天我要碰：<接口/模块名>，不动契约。
```

> 模块**不预先分派**。谁动手谁负责，但**动手前要报一句**，避免两个人同时改同一个接口。
> 要碰两个人共用的东西（`db_*`、`detectConflicts`、BLE 帧、token）→ **必须等另一人回一句「可以」**。

## 3. 每天收工（四件事）

> ⚠️ **这一步没做完，不许走。** 痕迹材料是赛事硬性要求，攒到最后一定补不全。

- [ ] **1. 跑一遍**：项目能起、控制台不报红、核心功能点得过。
- [ ] **2. 归档痕迹**：截图 / 导日志，丢进对应目录。
  - 码道 IDE 插件日志 → `.evidence/01-ide-plugin-logs/`
  - AI 对话与 Prompt 截图 → `.evidence/02-ai-prompts/`
  - 代码生成 / 重构 / 排错记录 → `.evidence/03-codegen-history/`
  - 文件命名：`yyyymmdd-一句话-谁.png`（例：`20261002-接入快递适配器骨架-小林.png`）
- [ ] **3. 补一行开发流水**：往 `docs/码道开发记录.md` 追加一行（日期 / 谁 / 干了啥 / 用码道做了什么）。
- [ ] **4. 群里发日报**（照抄模板）：

```
【日报 10/02】
做了：<一句话>
动了：<文件或接口名>
契约：没动 / 动了 §x.x（已升版本到 v2.0.1）
卡住：<一句话，没有就写「无」>
明天：<一句话>
```

## 4. 怎么跟 DeepSeek 提任务（模板）

**好提问 = 说清「哪一节契约 + 哪个文件 + 要什么效果」。**

```
按 SKILL.md §3.3 的 DataSourceAdapter 接口，
在 src/adapters/kuaidi100.ts 里写一个**桩实现**：
- fetch() 永远 resolve
- 返回 AdapterResult{ ok: true, source: 'kuaidi100', events: [1条假的 EventDraft], hints: [], error: null }
- 假数据的 externalId 用 'SF0000000001'，confidence 固定 0.6
- 不要接真实 API，不要写库
只输出这个文件的内容，并告诉我怎么验证它没跑偏。
```

**坏提问（会被队友骂）：**

| ❌ 坏提问 | 问题 |
| --- | --- |
| 「帮我写个日程功能」 | 太笼统，它必然乱造字段 |
| 「快递 API 怎么接」 | 本期明确**不接入**，问了也是白问 |
| 「把冲突判定改简单点」 | 动冻结规则，必须走变更流程 |
| 「随便写个好看的界面」 | 会得到跟 token 不符的第二套配色 |
| 「整个文件重写一下」 | 会把别人写的部分也一起冲掉 |

**收到代码后必做三问：**

1. 它用了契约里的哪个签名？有没有自己发明字段名？
2. 有没有偷偷引入依赖 / 网络请求 / 硬编码密钥？
3. 我怎么在 1 分钟内验证它？

## 5. 必须停下来问的五件事（固定话术）

| 触发条件 | 你该发的原话 |
| --- | --- |
| 要改契约里的字段 / 签名 / 枚举 / UUID / token | 「这会动到冻结的接口 `xxx`（§3.x），按 §6 要先升版本并同步所有人。确认了我再写。」 |
| 要真实接入某个数据源（快递100 / 教务 / 12306） | 「本期契约写的是只留接口不接入。要提前接的话，我先冻结适配器行为，确认吗？」 |
| 要加一个新依赖 | 「新依赖要先登记到 `docs/作品说明.md` 开源组件表（§2-5）。这个库的许可和来源我整理给你。」 |
| 要碰 §3.8 的蓝牙留白（主从角色 / MTU / 重连 / 权限） | 「这是契约里明确留白的部分，动之前得先定下来并写回 §3.8，确认吗？」 |
| 发现契约本身写错了 / 有歧义 | 「契约 §x.x 这里我看不懂，我理解为 A，另一种理解是 B。选哪个？」 |

> **不要自己猜。** 猜错一次，全队返工的时间够改十遍契约。

## 6. 常见翻车与求助顺序

| 症状 | 大概率原因 | 先做什么 |
| --- | --- | --- |
| 前端拿到 `undefined` | Rust 返回了 `start_at` | 查 `serde(rename_all = "camelCase")`（契约 §7-C1） |
| 时间差 8 小时 | 用了 `toISOString()` | 换契约 §3.1 的带偏移写法（§7-B1） |
| 页面白屏 | 坏 JSON 没兜住 | 解析包 `try/catch`，返回空快照（§7-B3） |
| 列表出现重复快递 | 没用 `dedupKey` | `source:externalId` 全局唯一（§3.4） |
| 两个人结论不一致 | 各自实现了冲突判定 | 只许调 `detectConflicts()`（§3.6） |
| 症状莫名其妙 | — | **先 `git pull`**，一半的怪问题都是版本不一致 |

**求助顺序：契约 → 群里问 → 队长 → 指导老师。**
**「我改了别人的文件没告诉他」不是求助，是事故。**

## 7. 一页速查

| 项 | 值 |
| --- | --- |
| 契约文件 | `skills/pair-dev-contract/SKILL.md`（`shishi-protocol`，唯一权威） |
| 核心数据结构 | `ScheduleEvent`，id 前缀 `evt_` |
| 去重键 | `source:externalId` |
| 存储 key | `shishi:v2:events`（改结构就升号，旧 `v1` 不读） |
| 冲突函数 | `detectConflicts(events) → Record<id, ConflictHit[]>`，三条规则**全 warn** |
| UI 冲突标记 | `data-conflict="warn"`（UI 禁止自己判断冲突） |
| 时间格式 | ISO8601 **带 `+08:00`** |
| JSON 字段 | **camelCase**（Rust 侧 `serde rename_all`） |
| BLE Service | `d5f1c0de-0001-4a1e-9c2b-5f1e00000001` |
| BLE RX / TX | `...0002`（手机→桌面）/ `...0003`（桌面→手机） |
| BLE 单帧上限 | payload ≤ 200 字节，帧头 6 字节 |
| 真源 | **桌面端**，手机推送要等 `EVENT_ACK` |
| 未实现怎么写 | `E_NOT_IMPLEMENTED` + `message: '本期未接入'` |
| 视觉 | 马卡龙六色 + 玻璃拟态，token 见契约 §3.9 |

## 8. 三条最土的规矩

1. **契约先读，对表先过** —— 没过对表就开始写，等于闭着眼睛开车。
2. **每天收工截图归档** —— 这是赛事硬性材料，补不出来的。
3. **拿不准就问** —— 多问一句花一分钟，猜错一次花一天。
