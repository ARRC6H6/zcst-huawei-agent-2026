## 0. 一句话原则

> **契约是唯一的沟通渠道。**
> 你不用读队友的代码，队友也不用读你的；大家只对着**同一份契约**写。
> 所以 —— **契约没读、对表没过，不许动手写代码。**

## 1. 一分钟上手

### 第一步：把契约喂给你的 DeepSeek

每个新对话都要做一次（DeepSeek 不记得上一个对话）：

**方法 A（推荐）**：把 `skills/pair-dev-contract/SKILL.md` 上传到对话里。

**方法 B**：新建对话，第一条消息把契约全文粘进去。

### 第二步：发「对表」指令

直接复制这段：

```
请完整阅读我上传的 SKILL.md（实验助手 Lab Studio 软件接口契约，zhbit-lab-protocol v3），
然后逐题回答：

1. 核心数据结构叫什么？id 的前缀是什么？
2. 报告（report）存不存进 Exp 里？不存在的话存在哪个 key？
3. 时间戳用什么格式？为什么禁止 toISOString()？
4. 图片和视频分别怎么存？图片压缩参数是多少？IndexedDB 写失败怎么办？
5. 画布有没有 z 字段？层级靠什么决定？置顶的 action 叫什么？
6. 换仪器美术的唯一入口是哪个函数？规则是什么？
7. saveExp() 写入前后必须做哪几件事？isValidExp 的闸门条件是什么？
8. 新增一个按钮交互要改哪里？cv- 前缀的动作会被转给谁？
9. LLM 未配置或调用失败时的降级链是什么？
10. 存储层和网络层的失败表现有什么不同？各自允许抛异常吗？

每题都要引用契约里的章节号。答完先别写代码，等我确认。
```

### 第三步：拿下面这张表判分

**全对才继续。错一题就重新贴一遍契约，别将就。**

| # | 答案要点 | 出处 |
| --- | --- | --- |
| 1 | `Exp`（实验文件）；前缀 `exp_`（`uid("exp_")` 生成） | §3.1 |
| 2 | **不存在 `Exp` 里**。独立存 `zhbit-lab-report:<expId>`；只在导出单实验时一起打进 `kind:"zhbit-lab-experiment"` 的包 | §3.1 / §3.6.1 / §3.8 |
| 3 | `Date.now()` **毫秒数**；毫秒数天然无时区，ISO 字符串会带来 8 小时/时区漂移，且显示统一走 `fmtDate()` | §2-3 |
| 4 | 图片：`compressImage()`（最长边 ≤ **1280**、`image/jpeg`、`quality 0.82`）→ `Media.put()` 进 IndexedDB（db `zhbit-lab` / store `media`）；**put 失败自动把 `store` 改成 `"external"` 并照常返回**。视频：只登记元信息，`store` 恒为 `"external"`，不进 IndexedDB | §3.3 |
| 5 | **没有 `z` 字段**。层级 = `items` **数组顺序，末尾为最上层**；置顶 `cv-front`（push 末尾）、置底 `cv-back`（unshift 开头） | §3.4 |
| 6 | `renderInstIcon(item, size)`；`imageUrl` 非空则渲染 `<img>`（`object-fit: contain`），否则回退 `icon` 内联 SVG。换美术只给 `INST_LIB` 条目填 `imageUrl`，不许改画布/视图代码 | §3.5 |
| 7 | ① 先 `isValidExp()`，不合法则 toast + 返回 `false` 不写入；② 强制 `exp.updatedAt = Date.now()`；③ 强制 `exp.v = EXP_VERSION`；④ 先写 `KEYS.exp(id)`，再**按 id 覆盖**（不是追加）汇总列表 `KEYS.exps`。闸门：e 是对象 + `id` 非空字符串 + `steps` 是数组 + 每个 step 对象、`id` 是字符串、`images` 是数组 | §3.6.2 |
| 8 | 模板里写 `data-act="xxx"` + 在 `handleAct()` 加一个 `case`。**不许单独 `addEventListener`**；任何 `cv-` 前缀的动作由 `handleAct` 的 `default` 转给 `canvasAct()` | §3.7 |
| 9 | 未配置 `apiKey` → 直接走 `localReport()`；`callLLM` 抛错 → `llmReport()` catch → toast「LLM 调用失败…已降级本地生成」→ `localReport()`。**不许出现点了没反应** | §3.8 |
| 10 | **存储层（`Store`/`Media`）永不抛**，一律返回 `false` / `null` / `fallback`，要告知用户就 `toast()`；**只有网络层 `callLLM` 抛 `Error`**，由调用方 `try/catch` 降级 | §4 |

> 🔴 如果它答得含含糊糊、开始「一般来说」「通常建议」——说明没吃进去，重贴。

## 2. 每天开工（三件事）

- [ ] **1. 拉最新**：`git pull`，先看一眼昨天谁动了什么。
- [ ] **2. 看一眼契约有没有变**：打开契约末尾的**变更日志**，比对自己上次记的版本号。变了就重新对表。
- [ ] **3. 想清楚今天碰哪块**（对照 `src/README.md` 的区段分工表），然后在群里发一句：

```
今天我要碰：<index.html 第 x 区段 / 函数名>，不动契约。
```

> 区段**不预先分派**。谁动手谁负责，但**动手前要报一句**，避免两个人同时改同一个函数。
> 要碰两个人共用的东西（`Store`、`Media`、`canvasAct`、`REPORT_PROMPT`、`handleAct`、token）
> → **必须等另一人回一句「可以」**。
> ⚠️ 本项目是**单文件工程**，改动都在同一个 `src/index.html` 里，
> **动手前务必 `git pull`**，冲突起来比多文件工程更难合。

## 4. 怎么跟 DeepSeek 提任务（模板）

**好提问 = 说清「哪一节契约 + 哪个区段 + 要什么效果」。**

```
按 SKILL.md §3.4 的 canvasAct 动作集，在 index.html 第 7 区段（仪器画布）里加一个动作分支：
- action 名 "cv-note"，prompt 输入该仪器在本步的说明，写进选中项 CanvasItem.note
- 无选中时 toast("先点选一个仪器") 后 return，与 cv-label 的写法保持一致
- 不要动 items/links 结构，不要加新字段，不要改 handleAct
只输出 canvasAct 函数里新增的这一段，并告诉我怎么验证它没跑偏。
```

**坏提问（会被队友骂）：**

| ❌ 坏提问 | 问题 |
| --- | --- |
| 「帮我写个实验助手」 | 太笼统，它必然乱造字段、乱引库 |
| 「整个 index.html 重写一下」 | 2000 行一次性冲掉，队友的区段全没了 |
| 「引入一个 markdown 库渲染更漂亮」 | 违反铁律 1（零依赖），`check-page` 直接判死 |
| 「把图片存进 localStorage 简单点」 | 违反 §3.3 冻结的存储分工，配额还会爆 |
| 「随便写个好看的界面」 | 会得到跟 token 不符的第二套配色，深色必崩 |
| 「加个后端把数据同步一下」 | 本期明确无后端，问了也是白问 |

**收到代码后必做三问：**

1. 它用了契约里的哪个签名？有没有自己发明字段名 / 新 `data-act`？
2. 有没有偷偷引外部依赖 / 加 `fetch` / 硬编码密钥 / 直接写 `localStorage`？
3. 我怎么在 1 分钟内验证它？（最先想到 `node src/tools/check-page.mjs src/index.html`）

## 6. 常见翻车与求助顺序

| 症状 | 大概率原因 | 先做什么 |
| --- | --- | --- |
| 打开一片白 | 读到坏 JSON / 渲染抛异常 | 所有读存储走 `Store.readJSON`；`normalizeExp` 补默认值（契约 §3.6.2） |
| 界面显示 `undefined` | 老数据缺新字段 | 读取先 `normalizeExp`（§3.6.2） |
| 刷新数据全丢 | 改了 `state.exp` 没落盘 | 走 `persistExp()` / `saveSoon()`（§3.7） |
| 存不进去还弹「结构不合法」 | `isValidExp` 闸门没过（缺 `steps` / step 缺 `images`） | 造数据一律走 `newExp()` / `normalizeStep()`（§3.6.2） |
| 列表出现两条同名实验 | `saveExp` 追加而不是按 id 覆盖 | 先 `filter` 再 push（§3.6.2） |
| 新按钮点了没反应 | 只写了模板没加 `handleAct` case | `data-act` + `handleAct`（§3.7） |
| 画布仪器层级不对 | 以为有 `z` 字段 | 层级 = `items` 数组顺序，用 `cv-front`/`cv-back`（§3.4） |
| 手机上拖不动仪器 | 用了 mouse 事件 | 一律 Pointer Events（§7-C1） |
| 点「分发给 LLM」没反应 | 没接降级链 | 无 Key → 本地生成 + toast（§3.8） |
| 深色下某块是白的 | 裸写 `#fff` 或漏了深色覆盖 | 只用 `var(--x)`（§3.9） |
| 校验挂了但「我这边是好的」 | 改到了校验覆盖的契约点 | 跑 `node src/tools/check-page.mjs src/index.html` 看具体哪条红 |
| 症状莫名其妙 | — | **先 `git pull`**，一半的怪问题都是版本不一致 |

**求助顺序：契约 → 群里问 → 队长 → 指导老师。**
**「我改了别人的区段没告诉他」不是求助，是事故。**

## 7. 一页速查

| 项 | 值 |
| --- | --- |
| 契约文件 | `skills/pair-dev-contract/SKILL.md`（`zhbit-lab-protocol`，唯一权威） |
| 作品源码 | **单文件** `src/index.html`（约 2000 行，按 13 个区段注释定位） |
| 核心数据结构 | `Exp`，id 前缀 `exp_` |
| 报告存储 | 独立 key `zhbit-lab-report:<expId>`（**不在 `Exp` 里**） |
| 存储 key 前缀 | `zhbit-lab-` |
| 结构版本号 | `EXP_VERSION = 1`（改结构就 +1） |

| 视频 | 只登记元信息，`store: "external"` |

| 视觉 | 马卡龙六色（`t-paper/mint/peach/lavender/lemon/sky`）+ 柔光玻璃，token 见契约 §3.9 |

## 8. 三条最土的规矩

1. **契约先读，对表先过** —— 没过对表就开始写，等于闭着眼睛开车。
2. **每天收工截图归档** —— 这是赛事硬性材料，补不出来的。
3. **拿不准就问** —— 多问一句花一分钟，猜错一次花一天。
