# 实验助手 · 需求与设计蓝图

> 项目：珠海科技学院 / 大学生化实验辅助工具「实验助手」
> 参考：`正式项目/demo`（珠海科技学院·生活便利助手）——**仅借鉴其单文件编写方案与柔光玻璃 + 马卡龙六色美术风格**，业务模块一律不迁移
> 依据：`交付计划/新工作方案.png` + 两轮需求澄清问答
> 状态：**需求已定型，进入实施**
> 日期：2026-10-01

---

## 0. 一句话定位

把「一次生化实验」做成一份**可编辑、可播放、可分享的流程文件**：老师或学生先在编辑模式里把每个反应步骤写清楚（文字 / 图片 / 视频 / 反应方程式 / 安全小 TIPS）并在画布上自由摆好仪器，合并成一份可分享文件；实验时切到记录模式逐步播放、边做边记录；最后把分步记录与总记录交给 LLM（或本地）生成实验报告参考版。

---

## 1. 业务主流程（对齐工作方案图）

```
实验助手
  └─ 编辑模式（老师学生都可编辑）
       └─ 填写反应步骤
            ├─ 文字描述
            ├─ 图片
            ├─ 视频
            ├─ 反应方程式        ← 主流程延续
            ├─ 安全小 TIPS
            └─ 仪器摆放画布（每步一张）
       └─ 合并为可分享文件  ──►  .json 实验文件
  └─ 记录模式
       └─ 每步按已编辑文件播放（逐步只读展示，可上下步）
            ├─ 分步记录板块（每步的图文 / 现象 / 数据）
            └─ 总记录板块（整场备注与异常）
  └─ 分发给 LLM（用户自接；无 API 则本地生成 markdown 表格）
       └─ 合并为实验报告参考版
```

## 3. 数据模型

### 3.1 实验文件（可分享 / 可导入导出）

```js
{
  v: 1,                          // 结构版本号
  id: "exp_xxx",
  name: "银镜反应",
  subject: "chemistry" | "biology",
  desc: "实验简介",
  createdAt: 1727740800000,
  updatedAt: 1727740800000,
  steps: [ Step, ... ],
  log: {                         // 记录模式产出
    total: "",                   // 总记录：整场备注与异常
    totalImages: [ mediaRef ],   // 总记录附图
  },
  report: {                      // 报告页产出
    mode: "local" | "llm",
    markdown: "",
    generatedAt: null,
    model: "",
  },
}
```

### 3.2 步骤 Step

```js
{
  id: "s1",
  title: "步骤标题",
  text: "文字描述",
  equation: "Ag+ + e- = Ag",     // 反应方程式（纯文本，展示时等宽）
  tips: "安全小 TIPS",
  images: [ mediaRef ],          // 图片（IndexedDB）
  videos: [ mediaRef ],          // 视频：第一阶段仅占位（name/url）
  canvas: { w: 1000, h: 620, items: [ CanvasItem ], links: [ Link ] },
  record: {                      // 记录模式下本步的记录
    note: "",
    images: [ mediaRef ],
  },
}
```

### 3.3 媒体引用 mediaRef

```js
{
  id: "m_xxx",
  kind: "image" | "video",
  name: "现象.jpg",
  type: "image/jpeg",
  size: 123456,
  store: "idb" | "external",     // 图片走 idb；视频第一阶段走 external（只存文件名/链接）
  url: "",                       // external 时的外链（可空）
  w: 0, h: 0,
}
```

- **图片**：读入后压缩（最长边 ≤ 1280、quality 0.82），以 Blob 存 IndexedDB（库 `zhbit-lab`，表 `media`），页面内用 `URL.createObjectURL` 展示。
- **视频**：第一阶段不落地文件，只保存 `name` / 可选 `url` 占位；`store:"external"`。后续原生端接管。
- 导出 `.json` 时默认**不内嵌图片二进制**，导出为「引用占位 + 可选打包」；单实验文件保持轻量，图片随设备 IndexedDB 走。

### 3.4 画布 CanvasItem / Link

```js
CanvasItem = {
  id: "i_xxx",
  inst: "beaker",        // 仪器库 id
  x: 320, y: 180,        // 左上角坐标
  rot: 0,                // 旋转角度
  scale: 1,              // 缩放
  flip: false,           // 水平翻转（可选）
  label: "50mL 烧杯",    // 覆盖标签（可空则用库中 name）
  note: "",              // 该仪器在本步的说明
  z: 1,
}

Link = {
  id: "l_xxx",
  from: "i_a", to: "i_b",
  kind: "导管" | "导线" | "示意",
  note: "",
}
```

## 4. 仪器资源接口（重点：留接口，方便后续加美术）

### 4.1 仪器库条目 `INST_LIB`

```js
{
  id: "beaker",              // 唯一键
  name: "烧杯",
  cat: "glass",              // 分类：glass 玻璃器皿 / metal / support 支架 / heat 加热 / measure 计量 / biology 生物 / other
  icon: "<svg .../>",        // 内联 SVG 线稿占位（默认渲染）
  imageUrl: "",              // ★ 接口：填写后优先渲染图片，覆盖 SVG
  w: 90, h: 90,              // 默认尺寸（画布未缩放时）
  ratio: 1,                  // 宽高比，用于图片自适应
}
```

**替换美术的规则**：后续只需给对应条目填 `imageUrl`（或新增条目），画布渲染层优先取 `imageUrl`，取不到才回退 `icon` SVG。渲染函数 `renderItem()` 是唯一入口，任何新增仪器都无需改画布逻辑。

### 4.2 初始仪器清单（占位，可增删）

- **玻璃器皿**：试管、烧杯、锥形瓶、圆底烧瓶、容量瓶、量筒、滴管、玻璃棒、漏斗、蒸发皿、坩埚、表面皿、试剂瓶
- **计量 / 通用**：电子天平、温度计、pH 试纸、移液枪、移液管、洗瓶、铁架台、铁圈、石棉网、试管夹、坩埚钳
- **加热**：酒精灯、本生灯、水浴锅、电炉
- **生物**：显微镜、培养皿、接种环、离心管、离心机、电泳仪、恒温培养箱、酒精棉

> 以上均先用内联 SVG 线稿占位；美术资源到位后逐个补 `imageUrl`。

## 5. 编辑器与画布交互

| 能力 | 交互 |
|---|---|
| 新增仪器 | 左侧仪器库面板点击 / 拖入画布 |
| 拖拽摆放 | 指针按住仪器拖动，吸附网格（10px），实时更新 x/y |
| 缩放 | 选中后拖角柄或工具栏 +/−；`scale ∈ [0.4, 2.5]` |
| 旋转 | 选中后拖旋转柄或工具栏 ↺/↻；吸附 15° |
| 复制 / 删除 | 选中后工具栏复制 / 删除；`Delete` 键删除 |
| 连线 | 工具模式切到「连线」，点两个仪器生成 Link；可设类型与备注 |
| 选中与层级 | 点选高亮；置顶/置底 |
| 缩略与适配 | 画布固定逻辑坐标，容器按宽度等比缩放（响应式） |

**触控适配**：所有交互统一走 Pointer Events（`pointerdown/move/up`），一套代码兼容鼠标与触摸，符合三端自适应要求。

## 6. 记录模式

- **播放器**：顶部「步骤 1 / N」+ 上一步 / 下一步；主区逐步只读展示该步五要素与仪器图（画布以只读模式渲染，不可编辑）。
- **分步记录**：在播放当前步时，可就该步写现象/数据备注、追加图片（写入 `step.record`）。
- **总记录**：整场实验的备注与异常，写入 `exp.log.total`（附图可选）。
- 播放态与编辑态共用同一份画布渲染函数，仅 `readonly` 标志不同。

## 7. 报告与 LLM 接入

### 7.1 报告结构（国内高校通用生化实验报告规范）

| 字段 | 来源 |
|---|---|
| 实验名称 | `exp.name` |
| 实验目的 | 用户填写 / LLM 归纳 |
| 实验原理 | 用户填写，含反应方程式（汇总各步 `equation`） |
| 仪器与试剂 | 由各步画布 `items` 去重汇总 + 用户补充 |
| 实验步骤 | 各步 `title` + `text`，编号列表 |
| 实验现象与数据 | 各步 `record.note` + 记录图片 |
| 数据处理与结果 | 用户填写 / LLM 归纳 |
| 结论 | 用户填写 / LLM 归纳 |
| 讨论与误差分析 | 用户填写 / LLM 归纳 |
| 思考题 | 用户填写 / LLM 归纳 |
| 注意事项 | 汇总各步 `tips` |

字段支持增删（每个字段标题可编辑，可禁用空字段）。

### 7.2 LLM 接入约定

- **兼容协议**：OpenAI 兼容 `POST {baseUrl}/chat/completions`，`Authorization: Bearer {apiKey}`，body `{ model, messages, temperature }`。
- **配置**：设置页填写 `baseUrl` / `apiKey` / `model`，存 `localStorage['zhbit-lab-llm']`（apiKey 仅本机，导出实验文件时**不包含**）。
- **提示词模板**：项目内置 `REPORT_PROMPT`（含角色、实验数据 JSON、输出结构要求、markdown 输出约束），用户可在设置页查看/微调。
- **降级**：未配置或请求失败 → 走 `buildLocalMarkdown()` 本地生成 markdown 表格，页面明示「本地生成（未接入 LLM）」。
- **图片**：可选把记录图片作为 `image_url`（base64 data URL）随消息发送（需模型支持视觉），失败自动退回纯文本。

### 7.3 本地 markdown 表格形态（无 API 时的兜底）

```markdown
## 实验现象与数据

| 步骤 | 操作 | 现象/数据 | 备注 |
| --- | --- | --- | --- |
| 1 | 加入硝酸银溶液 | 溶液澄清 | |
| 2 | 水浴加热 | 试管壁出现银镜 | 见附图 1 |
```

## 8. 存储与持久化

| 数据 | 存储 | 键/库 |
|---|---|---|
| 实验列表元信息 | localStorage | `zhbit-lab-exps` |
| 单个实验（含步骤/记录/报告） | localStorage | `zhbit-lab-exp:<id>` |
| 图片 Blob | IndexedDB | db `zhbit-lab` / store `media` |
| 主题选择 | localStorage | `zhbit-lab-theme` |
| LLM 配置 | localStorage | `zhbit-lab-llm` |

- 全部读写经统一 `Store` 模块，写入前走 `isValidExp` 结构校验，脏数据拒绝入库。
- localStorage 写入失败（超限）时提示用户导出备份。

## 9. 美术规范（沿用 demo 基准）

- 令牌体系、六色马卡龙、单一缓动 `cubic-bezier(0.16,1,0.3,1)`、`158deg` 玻璃渐变、`saturate(180%)`、带蓝投影、`#1a1f33` 近黑文字、`10–15px` 密字号阶梯、内联 SVG 图标（stroke 1.8 / currentColor）全部继承。
- **深色**：只写一份 `:root[data-theme="dark"]` 令牌，跟随系统在 JS 解析成 `data-theme`。
- **配色-功能对应**：编辑 → 天空 / 记录 → 蜜桃 / 报告 → 柠檬 / 设置 → 薰衣草 / 首页中性云白。
- **移动端**：正文 ≥14px，触控目标 ≥44px，`hover` 一律补 `:active` 等价反馈。
- **新增样式**：仪器画布、链接线、播放器、markdown 预览、表格（`tabular-nums`）。

## 10. 三端自适应与后续双端 / 蓝牙演进

**第一阶段（现在）**：单文件 HTML，桌面/平板横向双栏优先；手机断点（≤860px）切单栏 + 底部 Tab；画布按容器宽度等比缩放。

**后续（原生双端）**：

1. **数据层已按"文件即实验"设计**，`.json` 是跨端唯一交换格式，原生端只需实现同一 schema 的读写。
2. **蓝牙同步**：定义增量同步协议——每台设备维护 `exp.updatedAt` + `rev`（本地递增版本号），配对后交换设备 ID 与各实验版本，按「较新覆盖 + 冲突保留双方副本」合并。
3. **手机间互传**：复用同一协议，以 `.json` 分片经 BLE 传输；无 BLE 时降级为二维码/文件分享。
4. 画布与媒体引用已抽象为 `CanvasItem` / `mediaRef`，原生端可原样渲染或替换为本地路径。

> 第一阶段会预留 `sync` 模块空实现与 `rev` 字段，保证后续接入不破坏现有数据结构。
