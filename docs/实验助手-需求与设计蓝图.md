### 0P.7 接手必读的 6 个坑（细节见 `README.md`）

1. `.ps1` 构建脚本**必须带 UTF-8 BOM**（本机只有 PowerShell 5.1，无 BOM 会中文乱码 + 一串语法错）。
2. **`--features custom-protocol` 不能删** —— 删了只在 **Android** 白 / 黑屏，Windows 测不出来。
3. 改了工程目录名 / 页面文件名后**必须整个 `cargo clean`**（Tauri 构建脚本把绝对路径写进了 `target`）。
4. 单文件 HTML 是**编译期内嵌**的 —— 改完 HTML 必须重编 Rust，否则打出陈旧前端。
5. 下载**必须走 Rust** `lan_file_download`（Android 的 wry 连 `DownloadListener` 都没有）。
6. `gen/android/.../MainActivity.kt` 是**手改过**的，别用 `cargo tauri android init` 覆盖（缩放会失效）。

## 0. 一句话定位

> ⚠️ **实况（2026-10-08）**：本节「在画布上自由摆好仪器」一句已不成立 —— 仪器摆放已于 2026-10-07 整体删除，
> 步骤只保留五要素。定位措辞请以 §0P.1 为准。

把「一次生化实验」做成一份**可编辑、可播放、可分享的流程文件**：老师或学生先在编辑模式里把每个反应步骤写清楚（文字 / 图片 / 视频 / 反应方程式 / 安全小 TIPS）并在画布上自由摆好仪器，合并成一份可分享文件；实验时切到记录模式逐步播放、边做边记录；最后把分步记录与总记录交给 LLM（或本地）生成实验报告参考版。

## 1. 业务主流程（对齐工作方案图）

```
实验助手
  └─ 编辑模式（老师学生都可编辑）
       └─ 填写反应步骤
            ├─ 文字描述
            ├─ 图片
            ├─ 视频
            ├─ 反应方程式        ← 主流程延续
            ├─ 安全小 TIPS
            └─ 仪器摆放画布（已经作废）
       └─ 合并为可分享文件  ──►  .json 实验文件
  └─ 记录模式
       └─ 每步按已编辑文件播放（逐步只读展示，可上下步）
            ├─ 分步记录板块（每步的图文 / 现象 / 数据）
            └─ 总记录板块（整场备注与异常）
  └─ 分发给 LLM（用户自接；无 API 则本地生成 markdown 表格）
       └─ 合并为实验报告参考版
```

## 3. 数据模型

### 3.1 实验文件（可分享 / 可导入导出）

```js
{
  v: 1,                          // 结构版本号
  id: "exp_xxx",
  name: "银镜反应",
  subject: "chemistry" | "biology",
  desc: "实验简介",
  createdAt: 1727740800000,
  updatedAt: 1727740800000,
  steps: [ Step, ... ],
  log: {                         // 记录模式产出
    total: "",                   // 总记录：整场备注与异常
    totalImages: [ mediaRef ],   // 总记录附图
  },
  report: {                      // 报告页产出
    mode: "local" | "llm",
    markdown: "",
    generatedAt: null,
    model: "",
  },
}
```

### 3.2 步骤 Step

```js
{
  id: "s1",
  title: "步骤标题",
  text: "文字描述",
  equation: "Ag+ + e- = Ag",     // 反应方程式（纯文本，展示时等宽）
  tips: "安全小 TIPS",
  images: [ mediaRef ],          // 图片（IndexedDB）
  videos: [ mediaRef ],          // 视频：第一阶段仅占位（name/url）
  canvas: { w: 1000, h: 620, items: [ CanvasItem ], links: [ Link ] },
  record: {                      // 记录模式下本步的记录
    note: "",
    images: [ mediaRef ],
  },
}
```

### 3.3 媒体引用 mediaRef

```js
{
  id: "m_xxx",
  kind: "image" | "video",
  name: "现象.jpg",
  type: "image/jpeg",
  size: 123456,
  store: "idb" | "external",     // 图片走 idb；视频第一阶段走 external（只存文件名/链接）
  url: "",                       // external 时的外链（可空）
  w: 0, h: 0,
}
```

- **图片**：读入后压缩（最长边 ≤ 1280、quality 0.82），以 Blob 存 IndexedDB（库 `zhbit-lab`，表 `media`），页面内用 `URL.createObjectURL` 展示。
- **视频**：第一阶段不落地文件，只保存 `name` / 可选 `url` 占位；`store:"external"`。后续原生端接管。
- 导出 `.json` 时默认**不内嵌图片二进制**，导出为「引用占位 + 可选打包」；单实验文件保持轻量，图片随设备 IndexedDB 走。

### 4.1 仪器库条目 `INST_LIB`

```js
{
  id: "beaker",              // 唯一键
  name: "烧杯",
  cat: "glass",              // 分类：glass 玻璃器皿 / metal / support 支架 / heat 加热 / measure 计量 / biology 生物 / other
  icon: "<svg .../>",        // 内联 SVG 线稿占位（默认渲染）
  imageUrl: "",              // ★ 接口：填写后优先渲染图片，覆盖 SVG
  w: 90, h: 90,              // 默认尺寸（画布未缩放时）

```

### 7.1 报告结构（国内高校通用生化实验报告规范）

> ⚠️ **实况（2026-10-08）**：两处与实现不符，需注意 ——

> ② 本节末尾「字段支持增删」**未实现**，本地 markdown 的章节是固定的（只生成 7 节，见 §0P.3）；
> ③「实验现象与数据」等章节的**图片只写张数**，不内嵌图片（`image_url` 送 LLM 亦未实现）。

| 字段 | 来源 |
|---|---|
| 实验名称 | `exp.name` |
| 实验目的 | 用户填写 / LLM 归纳 |
| 实验原理 | 用户填写，含反应方程式（汇总各步 `equation`） |
| 仪器与试剂 | 由各步画布 `items` 去重汇总 + 用户补充 |
| 实验步骤 | 各步 `title` + `text`，编号列表 |
| 实验现象与数据 | 各步 `record.note` + 记录图片 |
| 数据处理与结果 | 用户填写 / LLM 归纳 |
| 结论 | 用户填写 / LLM 归纳 |
| 讨论与误差分析 | 用户填写 / LLM 归纳 |
| 思考题 | 用户填写 / LLM 归纳 |
| 注意事项 | 汇总各步 `tips` |

字段支持增删（每个字段标题可编辑，可禁用空字段）。

### 7.2 LLM 接入约定

- **兼容协议**：OpenAI 兼容 `POST {baseUrl}/chat/completions`，`Authorization: Bearer {apiKey}`，body `{ model, messages, temperature }`。
- **配置**：设置页填写 `baseUrl` / `apiKey` / `model`，存 `localStorage['zhbit-lab-llm']`（apiKey 仅本机，导出实验文件时**不包含**）。
- **提示词模板**：项目内置 `REPORT_PROMPT`（含角色、实验数据 JSON、输出结构要求、markdown 输出约束），用户可在设置页查看/微调。
- **降级**：未配置或请求失败 → 走 `buildLocalMarkdown()` 本地生成 markdown 表格，页面明示「本地生成（未接入 LLM）」。
- **图片**：可选把记录图片作为 `image_url`（base64 data URL）随消息发送（需模型支持视觉），失败自动退回纯文本。

## 10. 三端自适应与后续双端 / 蓝牙演进

**第一阶段（现在）**：单文件 HTML，桌面/平板横向双栏优先；手机断点（≤860px）切单栏 + 底部 Tab；画布按容器宽度等比缩放。

**后续（原生双端）**：

1. **数据层已按"文件即实验"设计**，`.json` 是跨端唯一交换格式，原生端只需实现同一 schema 的读写。
2. **蓝牙同步**：定义增量同步协议——每台设备维护 `exp.updatedAt` + `rev`（本地递增版本号），配对后交换设备 ID 与各实验版本，按「较新覆盖 + 冲突保留双方副本」合并。
3. **手机间互传**：复用同一协议，以 `.json` 分片经 BLE 传输；无 BLE 时降级为二维码/文件分享。
4. 画布与媒体引用已抽象为 `CanvasItem` / `mediaRef`，原生端可原样渲染或替换为本地路径。

> 第一阶段会预留 `sync` 模块空实现与 `rev` 字段，保证后续接入不破坏现有数据结构。
